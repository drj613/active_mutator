# 0.4.0: Configurable Spec Paths (#35) + Ledger Re-Audit (#34) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the tool's hard-coded `spec/` assumption configurable (`spec_paths`, default `["spec"]`) so projects with tests outside `spec/` get correct coverage baselines and phase-2 escalation, then re-audit the 47-entry equivalent-mutant ledger before tagging 0.4.0.

**Architecture:** A new `Config#spec_paths` member (list of directories relative to root, default `["spec"]`) threads through every site that currently hard-codes `spec/`: CLI/config-file parsing, `BaselineDelta` (classification, support-file trigger, spec glob), `Baseline` (digest glob, subprocess env), `baseline_hooks` (coverage exclusion filter), and `Runner` (escalation glob, `convention_spec_rel`, `preload_spec_helper!`). The shared spec-file glob lives in one class method, `BaselineDelta.spec_file_contents`, used by both the delta and the escalation pass. Default behavior is byte-identical to today.

**Tech Stack:** Ruby, Prism, RSpec, fork-based workers. Self-mutation gate: `bundle exec exe/active_mutator lib --changed` must exit 0 at the end of every task.

**Standing protocol (every task):** TDD red → green; `bundle exec rspec` green before any commit; self-mutation gate before the task's final commit.

```ruby
    def self.diff_coverage(before, after, root, spec_paths: ["spec"])
      prefixes = spec_paths.map { |sp| "/#{sp}/" }

      after.each do |path, data|
```

### Task 7: Ledger re-audit (#34)

**Files:**
- Modify: `.active_mutator_accepted.json` (currently 47 entries)
- Possibly modify: `spec/**` (new killing tests), `lib/**` (structural refactors that eliminate accepted mutants)

This is judgment work with a fixed procedure, not feature code. Ground rule from the issue: **every removal must be justified** — the entry is stale (anchor gone) or the mutant is now killed by a real test. Never remove wholesale, never loosen the gate.

- [ ] **Step 1: Flag stale entries mechanically**

Write a scratch script (scratchpad, not committed — shipping this is #37) that, for each ledger entry, checks whether its `file` exists and its `original_snippet` still appears in that file (and `subject` still resolves if cheap to check). Output: entry index + reason. Read the ledger first to confirm the exact field names before writing the script.

- [ ] **Step 2: Remove stale entries**

Delete exactly the flagged entries from `.active_mutator_accepted.json`. Record each removal (file + one-line reason) in the commit message body.

- [ ] **Step 3: Verify the gate still holds after pruning**

```bash
bundle exec exe/active_mutator lib
```

Expected: exit 0. If a pruned entry was NOT actually stale (its mutant resurfaces as a survivor), the script's match was wrong — restore that entry and fix the script's matching before continuing.

- [ ] **Step 4: Re-challenge the remaining entries**

For each remaining entry, answer "is this still genuinely unkillable?":
- **Killable** → write the killing test, run the targeted self-mutation (`bundle exec exe/active_mutator lib --subject "<Subject#method>"`) to confirm the mutant now dies, remove the entry.
- **Avoidable by structure** → where cheap, apply the restructure patterns from past audits (e.g. `if/elsif/else` over guard-`return` chains, `extend self` over `module_function`), then kill + remove.
- **Truly equivalent** → keep, and make sure the entry's reason field says *why* in one sentence.

Batch the work: group entries by file, one commit per file or per theme, message explaining each kill/keep decision.

- [ ] **Step 5: Final gate + close**

```bash
bundle exec rspec && bundle exec exe/active_mutator lib
```

Expected: green, exit 0. Commit the final ledger with a summary (entries before → after, N killed, N stale, N kept-equivalent):

